# forbidden-subdomains.txt — SUBSTRING blocklist
#
# The daemon matches these entries as SUBSTRINGS against the normalised slug
# (Unicode NFKD + ASCII fold + lowercase + `[^a-z0-9]+` collapsed to `-`).
# One entry per line, `#` for comments, empty lines ignored, lowercased at
# load time. Reload on daemon restart:
#     sudo systemctl restart tooling-tenant-api
#
# Only put entries whose substring appearance in ANY legitimate French/English
# tenant slug is essentially impossible (very low false-positive risk).
# Terms with FP risk (`pute` in `computer`, `cul` in `masculin`, `bite` in
# `orbite`, …) go in forbidden-subdomains-word.txt (whole-word match) instead.
#
# When a buyer-supplied slug matches, the daemon SKIPS the normal
# `<base>-<NNNN>` collision retry (which would leave the offensive substring)
# and generates a fully random `<8 a-z>-<4 0-9>` slug via gen_random_tenant_id().
#
# Scope: substrings whose blocking is justified by French law risk
# (apologie du terrorisme / crimes contre l'humanité, injures ou provocations
# à la haine raciale / antisémite publiques, pédopornographie) OR clear
# obscenity/insult with no meaningful FP risk.
